LOSSLESS RE-EDITING

The original image is preserved.

Re-editing starts from:
originalImagePath

It does NOT repeatedly edit the previously processed JPEG.

Reopening a page restores the saved rotation, filter and crop
onto the original image, so the editor previews:

Original image + saved edit parameters

rather than the previously processed JPEG.

Therefore:

Original
↓
Crop / Rotate / Filter
↓
Processed image

Editing again starts from the original source rather than:

Processed JPEG
↓
Processed JPEG again
↓
Further degradation

This prevents JPEG-generation stacking and preserves edit quality as much as the processing pipeline allows.

IMPORTANT CROP DECISION

Crop is applied as a source rectangle BEFORE rotation/filter processing.

This is intentional.

It means repeated editing does not crop an already-cropped processed JPEG.

The original source remains the authoritative image for future edits.

KNOWN INTENTIONAL LIMITATIONS

JPG/PNG multi-page export is bundled into a single ZIP archive.

The ZIP is built by hand (store method, no compression) with no libraries.

A very large export can still hit browser memory limits.

localStorage image storage is limited.

Large numbers of/high-resolution documents can eventually hit the browser's storage ceiling.

Native share behavior depends on browser/device support.

When unsupported, download is used automatically.

Some advanced scanner features are intentionally absent.

This is by design, not unfinished accidental scope.
